# button·a의 의미와 키보드 접근성

학습·기록: 2026-10-21 (Asia/Seoul)
상태: 당일 학습 마무리. 요소 선택 기준과 설명 후 기본 키보드 동작 구분 확인. 새 조건의 독립 적용·지연 복습 미확인.

## 동작에는 button, 이동에는 a

HTML 요소는 겉모양뿐 아니라 의미와 기본 동작을 제공한다. 메뉴 열기처럼 사용자가 동작을 실행하려면 button, 상품 상세 주소로 이동하려면 href가 있는 a를 사용한다. 함수를 호출하는지 여부만으로 나누지는 않는다. 링크에서도 JavaScript 함수를 실행할 수 있지만, 사용자의 목적이 주소 이동이라면 링크가 적절하다.

```html
<button type="button" onclick="alert('메뉴 열기')">메뉴 열기</button>
<a href="/products/42">상품 상세 페이지로 이동</a>
```

버튼 예제는 실제 메뉴 구현 대신 알림으로 실행 여부를 보여준다. 링크는 해당 경로의 페이지가 있다고 가정한다. 보충 설명: type="button"은 폼 제출용이 아닌 일반 버튼을 명시한다. 링크는 다른 페이지뿐 아니라 같은 페이지 안의 위치로 이동할 때도 사용할 수 있다.

## 포커스 이동과 실행은 별개다

포커스는 현재 키보드 입력을 받을 대상이다. Tab으로 다음 대상, Shift + Tab으로 이전 대상으로 이동한다. Shift 단독으로 이동하는 것은 아니다. 포커스된 요소에는 보통 시각적인 테두리가 표시되어 현재 위치를 알 수 있다.

| 요소 | 기본 Tab 포커스 | 포커스된 상태의 실행 키 |
| --- | --- | --- |
| button | 가능 | Enter 또는 Space |
| a href="…" | 가능 | Enter |
| 일반 div | 불가능 | 기본 실행 동작 없음 |

링크의 Space는 일반적으로 페이지를 스크롤한다. 링크에는 주소 복사와 새 탭으로 열기 등 브라우저 기능도 있다. 위 표는 일반적인 활성 요소의 기본 동작이며, 운영체제·브라우저의 키보드 탐색 설정이나 disabled, tabindex, 이벤트 처리 등으로 달라질 수 있다. 모든 환경에서 관찰한 결과라는 뜻은 아니다.

버튼을 키보드로 실행하는 흐름은 다음과 같다.

1. Tab으로 버튼에 포커스를 옮긴다.
2. Enter 또는 Space로 버튼을 실행한다.
3. 브라우저가 버튼의 click 이벤트를 발생시킨다.
4. onclick에 연결한 코드가 실행되어 예제에서는 알림이 뜬다.

onclick은 마우스 전용이 아니다. 기본 button의 키보드 실행으로도 호출된다. 이 과정에 input이나 form은 필요하지 않다. 입력란에서 Enter를 눌러 폼이 제출되는 동작은 폼 구성에 따른 별도의 동작이며, 포커스된 버튼을 실행하는 것과 구분한다.

## onclick만 있는 div에 빠진 것

```html
<div onclick="alert('메뉴 열기')">메뉴 열기</div>
```

이 div는 마우스 클릭 시 알림을 표시할 수 있지만, onclick만 추가한다고 기본 Tab 탐색이나 Enter·Space 실행이 제공되지는 않는다. button은 접근성 정보에 버튼이라는 역할을 제공하므로 화면 읽기 프로그램이 버튼으로 안내할 수 있다. 일반 div에는 그 의미도 없다.

보충 설명: div에 tabindex="0"을 붙이면 Tab 포커스 대상으로 만들 수 있지만 버튼 역할과 실행 키까지 자동으로 생기지 않는다. role="button"도 의미를 전달할 뿐 키보드 동작을 구현해 주지는 않는다. 이 질문은 대화 중 제시했으나 사용자가 직접 답하지 않았으므로 이해 확인으로 집계하지 않는다. 기본 button을 사용하면 이러한 기본 기능을 직접 재구현할 필요가 없다.

예제의 한계: 실제 메뉴의 열림 상태 전달, 메뉴 내부 포커스 관리와 닫기 동작은 다루지 않았다. 예제는 설명용이며 이번 학습에서 브라우저 실행이나 보조기기 검증을 수행하지 않았다.

## 실제 답변과 피드백

아래는 실제 대화의 요약이며 직접 인용이 아니다.

- 최초에는 메뉴 열기는 동작을 수행하므로 button, 상품 상세 이동은 URL과 연결하므로 a를 선택했다. 기준은 정확하며 함수 호출 자체보다 사용자 목적이 중요하다고 보완했다.
- 버튼은 input 또는 form과 연결됐을 때 Enter로 제어할 수 있다고 설명했다. 폼 밖의 버튼도 포커스 후 Enter·Space로 실행할 수 있다는 점과 폼 제출의 차이를 설명했다.
- button과 div의 차이가 키보드 조작인지, 실제로 어떻게 조작하는지 질문했다. Tab 포커스 → 실행 키 → click 이벤트 → 연결한 코드 실행 흐름과 접근성 역할을 설명했다. 이후 이해했다고 응답했다.
- 마지막에는 버튼은 Enter·Space, 링크는 Enter로 실행하고 일반 div에는 해당 기능이 없다고 정리했다. 이동 키를 Tab과 Shift로 표현하여 마지막 피드백에서 이전 이동은 Shift + Tab이라고 교정했다. 이 표현만으로 전체 개념 이해를 낮게 평가하지 않는다.

마지막 정리는 설명을 보지 않고 하도록 안내했으나 실제 참고 여부는 미확인이다. 최종 답변은 키보드 동작 중심이며, 요소 선택 이유는 최초 답변에서 확인했다. 접근성 역할·링크 부가 기능·tabindex와 역할의 차이는 에이전트의 보충 설명으로 남긴다. 독립적인 코드 수정이나 지연 인출이 확인된 것은 아니다. 정식 복습 점수와 오류 횟수는 부여하지 않는다.

## 다음 확인

첫 복습 예정일은 2026-10-22다. 동작과 이동의 구분, 폼 밖 버튼 조작, Tab과 Shift + Tab, Enter·Space 차이를 학습 범위 안에서 확인한다. 새로운 조건의 요소 선택·수정과 장기 유지는 미확인이다. 다음 새 학습은 브라우저 이벤트 전파와 기본 동작이며, 오늘의 click 및 링크 이동과 연결한다.
