# 이벤트 루프와 Promise 실행 순서

학습 시작: 2026-10-20 · 마무리 및 기록: 2026-10-21 (Asia/Seoul)
상태: 설명 후 이해 및 새 조건의 실행 순서·이유 설명 확인. 장기 숙달과 정식 지연 복습은 미확인.

## 1. 함수 호출과 콜백 예약은 다르다

동기 실행은 현재 작업이 끝나야 다음 코드로 넘어가는 방식이다. 비동기 처리는 결과를 기다리는 동안 현재 실행 흐름이 다음 코드로 진행할 수 있게 한다. 단순히 작업이 오래 걸린다는 뜻은 아니다.

```js
function hello() {
  console.log("안녕");
}

hello();                 // 지금 직접 호출
setTimeout(hello, 1000);  // hello를 전달해 나중에 호출하도록 예약
console.log("끝");
```

예상 출력: 안녕 → 끝 → (타이머 실행 시점에) 안녕.

setTimeout 자체는 지금 호출된다. 지금 하는 일이 타이머 등록이고, 전달한 hello의 호출은 나중이다. 함수를 전달하는 hello와 지금 호출하는 hello()를 구분해야 한다.

콜백은 다른 함수에 전달하여 그쪽에서 호출하도록 하는 함수다. 보충 설명: 콜백이라는 이름 자체가 비동기를 뜻하지는 않는다. 이번에 다룬 then 콜백과 타이머 콜백은 나중에 실행되는 사례다.

## 2. 콜 스택과 큐

| 구조 | 역할 | 이번 예제에서의 의미 |
| --- | --- | --- |
| 콜 스택 | 실행 중인 함수와 돌아갈 호출 지점을 관리 | 함수를 호출하면 들어가고, 끝나면 빠져 호출한 곳으로 돌아옴 |
| 태스크 큐 | 실행할 태스크를 대기시킴 | 실행 시점이 된 타이머 콜백의 태스크 |
| 마이크로태스크 큐 | 마이크로태스크를 대기시킴 | 이행된 Promise에 연결한 then 콜백의 실행 |

큐는 먼저 들어온 항목을 먼저 꺼내는 대기 구조이고, 스택은 마지막으로 들어온 항목이 먼저 나오는 구조다. 직접 호출한 console.log나 일반 함수는 매번 태스크 큐에 새로 줄을 서지 않는다. 현재 실행 흐름에서 콜 스택을 통해 실행된다. 마이크로태스크와 태스크의 콜백 역시 실제 실행할 때는 콜 스택을 사용한다.

현재 코드가 이미 실행 중이면, 큐에 준비된 작업이 있어도 그 코드 사이에 끼어들지 않는다. 스크립트 실행 자체가 태스크로 시작할 수 있지만 그 안의 함수 호출마다 새로운 태스크가 생기는 것은 아니다.

## 3. 태스크와 마이크로태스크는 무엇이 다른가

| 구분 | 대표적인 예약 원인 | 처리 방식 |
| --- | --- | --- |
| 태스크(매크로태스크라고도 부름) | setTimeout/setInterval의 실행 시점 도달, 사용자 클릭·키보드 입력 처리 | 실행 가능한 태스크 하나를 선택해 실행 |
| 마이크로태스크 | Promise의 then/catch 후속 처리, queueMicrotask | 처리 시점에 큐가 빌 때까지 실행 |

짧거나 빠른 함수라서 마이크로태스크가 되는 것이 아니다. 사용하는 API의 규칙으로 정해진다. 모든 비동기 작업이 하나의 큐에 등록 순서대로 쌓이는 것도 아니다.

이번 학습 예제의 기본 흐름:

```text
현재 태스크의 동기 코드 완료
    ↓
대기 중인 마이크로태스크를 모두 처리
    ↓
다음 실행 가능한 태스크 하나 실행
    ↓
대기 중인 마이크로태스크를 모두 처리
    ↓
반복
```

마이크로태스크를 처리하다 추가된 마이크로태스크도 포함해 큐를 비운다. 반면 태스크 큐 전체를 한 번에 비우지는 않는다.

예제의 한계: 실제 브라우저에는 여러 태스크 큐와 화면 갱신 기회가 있다. 위 흐름은 이번 타이머·Promise 예제를 위한 설명이며 모든 브라우저 스케줄링을 표현하지 않는다. 콜 스택이 비는 모든 순간을 무조건 하나의 동일한 처리 시점이라고 일반화하지 않는다.

처음 출제한 예제에 적용하면 다음과 같다.

```js
console.log("시작");
setTimeout(() => {
  console.log("타이머");
}, 0);
Promise.resolve().then(() => {
  console.log("Promise");
});
console.log("끝");
```

예상 출력: 시작 → 끝 → Promise → 타이머. 타이머를 먼저 등록했어도 현재 동기 코드가 먼저 끝나고, 준비된 마이크로태스크를 다음 타이머 태스크보다 먼저 처리한다. 이 예제의 Promise는 이미 이행됐다는 조건이 중요하다.

## 4. 타이머는 시간을 기다리는 동안 현재 코드를 막지 않는다

```js
console.log("시작");
setTimeout(() => {
  console.log("타이머");
}, 5000);
console.log("끝");
```

시작과 끝을 먼저 출력한다. 브라우저가 타이머 시간을 관리하고, 대기 시간이 지난 뒤 콜백을 실행할 태스크가 큐에 들어간다. console.log 한 줄을 별도 등록하는 것이 아니라 전달한 콜백 전체를 실행할 태스크가 생긴다.

5000ms는 정확한 실행 시각을 보장하지 않는다. 현재 동기 코드나 마이크로태스크 처리가 길어지면 더 늦게 실행된다. 0ms 역시 지금 즉시 콜백을 호출하라는 뜻이 아니다.

## 5. Promise 기본 사용법: 결과를 정하는 쪽과 받는 쪽

Promise는 성공 결과나 실패 이유를 전달받고 후속 처리를 연결하는 객체다. Promise가 내부의 모든 작업을 자동으로 비동기로 바꾸지는 않는다.

아래는 학습 중 다시 확인한 기본 사용 형태다. reject/catch는 사용 위치만 소개했고 오류 처리의 독립 적용은 아직 확인하지 않았다.

```js
const p = new Promise((resolve, reject) => {
  resolve("결과"); // 이 예제에서는 성공 결과를 정함
  // 실패하는 경우에는 대신 reject(실패이유)를 호출
});

p.then(value => {
  console.log(value); // 성공 결과를 받는 콜백
}).catch(error => {
  console.log(error); // 실패를 처리하는 콜백
});
```

resolve와 reject는 JavaScript가 생성자의 실행 함수에 제공하는 함수다. new Promise에 전달한 함수(executor)는 생성 중 즉시 동기적으로 호출된다. then을 호출하는 것과 then에 전달한 콜백이 실행되는 것은 별개다.

| 코드 | 지금 일어나는 일 | 나중에 일어나는 일 |
| --- | --- | --- |
| new Promise(executor) | Promise 생성 및 executor 호출 | executor가 예약한 작업이 있다면 그 API 규칙에 따라 실행 |
| Promise.resolve("결과") | 이 값으로 이행된 Promise를 얻음 | 그 자체로 별도 사용자 콜백을 실행하지 않음 |
| p.then(callback) | 후속 콜백을 등록 | p가 이행되면 콜백을 마이크로태스크로 실행 |

new Promise와 Promise.resolve는 Promise를 얻는 방법이고, then은 그 결과를 처리하는 방법이다. 보통 fetch처럼 이미 Promise를 반환하는 API를 사용할 때는 새로 감쌀 필요 없이 반환된 Promise에 then을 연결한다.

```js
const request = fetch("/api/users");
request.then(response => {
  console.log("응답 도착");
});
console.log("요청 시작했음");
```

이 예시는 서버가 있다고 가정한 설명용 코드이며 요청을 실행하지 않았다. 요청 시작 후 응답을 기다리지 않고 다음 줄로 진행한다. 아직 대기 중인 Promise의 콜백은 실행 가능한 마이크로태스크로 들어온 상태가 아니다. 따라서 네트워크 응답을 기다리는 then 콜백이 이미 준비된 타이머보다 항상 먼저 실행되는 것은 아니다.

## 6. Promise 내부 출력과 then 출력이 떨어져 나오는 이유

```js
console.log("시작");
const p = new Promise(resolve => {
  console.log("Promise 내부");
  resolve("결과");
});
p.then(value => {
  console.log(value);
});
console.log("끝");
```

예상 출력: 시작 → Promise 내부 → 끝 → 결과.

1. 시작을 출력한다.
2. new Promise가 executor를 즉시 호출하므로 Promise 내부를 출력한다.
3. resolve("결과")가 성공 결과를 정한다. 이 호출은 출력도, then 콜백의 직접 호출도 아니다.
4. then을 호출해 콜백을 등록한다. 이미 이행된 Promise이므로 실행할 마이크로태스크가 예약된다.
5. 현재 동기 코드의 끝을 출력한다.
6. 마이크로태스크를 처리할 때 콜백이 결과값을 받아 출력한다.

## 7. Promise로 감싸도 무거운 동기 작업은 그대로 실행된다

```js
Promise.resolve(heavyWork()).then(() => {
  console.log("후속 처리");
});
console.log("끝");
```

heavyWork는 오래 걸리는 동기 함수이고 일반 값을 반환한다고 가정한다. 함수의 인수는 호출 전에 평가하므로 heavyWork()를 먼저 끝까지 실행하고, 그 반환값을 Promise.resolve에 전달한다. 따라서 heavyWork가 끝나기 전에는 끝도 출력되지 않는다. 이후 끝 → 후속 처리 순서가 된다. heavyWork(함수 값 전달)와 heavyWork()(함수 호출)를 구분한다. 이 발췌는 heavyWork 구현이 없는 설명용 코드다.

보충 설명: async 함수 역시 첫 await까지는 동기적으로 실행되며, await 이후의 재개는 비동기적으로 처리된다. 자세한 사용법과 오류 처리는 다음 학습에서 다룬다.

## 8. 두 타이머 사이에 마이크로태스크가 실행되는 예제

```js
setTimeout(() => {
  console.log("타이머 1");
  Promise.resolve().then(() => {
    console.log("마이크로");
  });
}, 0);

setTimeout(() => {
  console.log("타이머 2");
}, 0);
```

예상 출력: 타이머 1 → 마이크로 → 타이머 2.

첫 번째 타이머 콜백이 마이크로태스크를 예약하고 종료하면, 두 번째 타이머 태스크로 넘어가기 전에 그 마이크로태스크를 실행한다. 마이크로태스크 처리 후에는 다음 태스크로 돌아간다. 값 자체가 큐에 들어가는 것이 아니라 해당 값을 출력할 콜백의 실행이 예약된다.

위 예제들은 대화에서 사용한 설명을 복습용으로 정리한 것이다. 아래에 별도로 명시한 마무리 적용 문제 외에는 실행 검증했다고 주장하지 않는다.

## 학습 중 질문과 교정

다음은 실제 대화의 요약이며 직접 인용이 아니다.

- 최초 예측은 시작 → 끝 → 타이머 → Promise였다. 동기 코드 우선은 맞았으나 비동기 콜백이 모두 하나의 큐에서 등록 순서대로 실행된다고 생각했다. 태스크와 마이크로태스크의 구분을 설명했다.
- 모든 함수 호출이 큐에 등록되는지 질문했다. 콜 스택에서의 즉시 호출과 큐에서 대기하는 작업을 구분한 뒤 직접 호출은 현재 코드 안에서 실행된다고 답했다.
- Promise 전체가 비동기인지, 무거운 작업을 감싸면 어떻게 되는지 질문했다. 인수 평가·생성자 실행·then 호출은 동기적이고 후속 콜백은 별도로 예약됨을 설명했다.
- Promise.resolve와 new Promise를 번갈아 보여준 설명 때문에 생성 방식과 콜백 실행 시점이 혼동됐다. 생성자의 resolve/reject 인자, 결과를 정하는 동작, 외부 then 콜백을 단계별로 다시 설명한 뒤 이해했다고 응답했다. 이 어려움을 학습자만의 개념 오류로 단정하지 않는다.

## 마무리 적용 문제와 실제 답변

기존 예제와 달리 타이머 콜백 안에서 Promise를 생성했다. 설명과 실행 결과를 보지 않고 풀도록 안내했고, 정답이나 추가 힌트 없이 다음 답변을 받았다. 실제 참고 여부는 별도로 확인하지 않았으므로 자료 없는 독립 인출을 확정하지 않는다.

```js
console.log("A");
setTimeout(() => {
  console.log("B");
  const p = new Promise(resolve => {
    console.log("C");
    resolve("D");
  });
  p.then(value => {
    console.log(value);
  });
  console.log("E");
}, 0);
console.log("F");
```

사용자 예측: A → F → B → C → E → D.

사용자 이유 요약: A를 출력하고 타이머 콜백을 예약한 뒤 F를 출력한다. 현재 실행과 마이크로태스크 처리가 없으면 타이머 작업을 실행한다. B와 Promise 내부 C는 동기적으로 실행되고, then의 동작은 마이크로태스크로 넘어가므로 E 다음에 D가 출력된다.

평가: 순서와 핵심 이유가 정확하다. 새 조건에 대한 적용 근거로 기록한다. 용어상 D라는 값 자체가 큐에 들어가는 것이 아니라 D를 출력할 then 콜백의 실행이 예약된다. 타이머 태스크는 대기 시간이 지난 뒤 큐에 들어간다. 이 표현 보완은 핵심 이해의 실패로 집계하지 않는다.

답변 이후 에이전트가 Node.js v20.20.2에서 위 코드를 실행해 A F B C E D 출력을 확인했다. 브라우저에서 직접 실행 검증하지는 않았다. 이 예제 결과로 Node와 브라우저의 모든 이벤트 루프 동작이 같다고 일반화하지 않는다. 대화의 다른 예제는 실행 검증하지 않았다.

## 다음 확인과 범위

학습을 마무리했으며 추가 평가 문제로 종료를 지연하지 않는다. 정식 복습 세트가 아닌 학습 마무리이므로 복습 점수·실패 횟수를 부여하지 않는다.

- 다음 학습: async/await와 오류 처리. Promise 기본 사용법을 연결해서 시작한다.
- 다음 복습: 태스크 안의 마이크로태스크 순서, 동기 함수 호출과 콜백 예약 구분.
- 미확인: 거부 처리와 체이닝, 대기 중인 Promise를 포함한 새 코드의 독립 적용, 장기간 기억 유지.
- 보충 설명: resolve에 Promise나 thenable을 전달하면 그 상태를 따를 수 있으므로 resolve 호출이 언제나 즉시 이행을 뜻하지 않는다. 이 세부 동작은 평가 범위 밖이다.

## 마무리 후 추가 확인 — 2026-10-21

then에 전달해 나중에 호출되는 함수를 콜백이라고 부른다는 점을 설명했다. 사용자는 매크로태스크 큐도 한 번에 모두 비우는지 질문했다. 첫 번째 타이머가 Promise 콜백을 예약하고 두 번째 타이머가 대기하는 예제로, 태스크 하나가 끝날 때마다 마이크로태스크를 모두 처리함을 설명했다.

사용자 최종 정리 요약: 첫 번째 타이머에서 타이머 1을 출력하고 then 콜백을 마이크로태스크로 예약한다. 첫 번째 태스크가 끝나면 마이크로를 출력하고, 다음 태스크에서 타이머 2를 출력한다.

피드백: 흐름과 이유가 정확하다. 설명과 출력 순서를 제공한 뒤의 자기 설명이므로 추가 독립 적용이나 지연 복습 성공으로 집계하지 않는다. 해당 두 타이머 예제는 실행 검증하지 않았다. 사용자가 학습 종료를 명시했으며 다음 주제와 복습 예정일은 유지한다.
